# 战线 1914 · 比利时战役

一个单文件网页战棋原型：六角格、Step 损失制、士气/组织度、征兵系统、可编辑兵种与地图。

**纯静态，零依赖，零后端。** 打开即玩。

---

## 在线试玩

部署到 GitHub Pages 后：

| 页面 | 地址 |
|---|---|
| 游戏 | `https://<你的用户名>.github.io/<仓库名>/` |
| 编辑器 | `https://<你的用户名>.github.io/<仓库名>/editor.html` |

## 目录结构

```
.
├── index.html      游戏本体（含内嵌 JSON 数据块）
├── editor.html     编辑器（含同一份数据块作为兜底）
├── gamedata.json   当前数据导出，可在游戏里用「载入」直接导入
├── .nojekyll       告诉 GitHub Pages 不要用 Jekyll 处理
└── README.md
```

> 两个 HTML **互不依赖**，但要**放在同一目录**——编辑器的「从游戏载入」会读取同目录的 `index.html` 来同步最新数据。分开放也能用，只是无法自动同步。

## 部署到 GitHub Pages

### 方式一：网页上传（不需要装 git）

1. 在 GitHub 新建仓库，比如 `frontline-1914`，选 **Public**
2. 进入仓库 → **Add file → Upload files**
3. 把本目录里的文件全部拖进去（`index.html`、`editor.html`、`gamedata.json`、`README.md`、`.nojekyll`）
   - `.nojekyll` 是隐藏文件，macOS 用 `Cmd+Shift+.` 显示，Windows 在「查看」里勾选「隐藏的项目」
   - 拖不进去也没关系，跳过它不影响运行
4. **Commit changes**
5. 仓库 → **Settings → Pages**
   - Source 选 **Deploy from a branch**
   - Branch 选 **main**，目录选 **/ (root)**
   - **Save**
6. 等 1–2 分钟，地址就是 `https://<用户名>.github.io/<仓库名>/`

### 方式二：命令行

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

然后同上开启 Pages。

### 方式三：已有 GitHub Pages 仓库

如果你已经有 `<用户名>.github.io` 仓库，直接把文件放到子目录（如 `frontline/`），访问 `https://<用户名>.github.io/frontline/` 即可。

## 游戏操作

- **点击**己方单位选中 → 点高亮格移动 → 点红框敌军攻击
- 底部 **征兵**：在据守的城镇或后方集结区组建部队（消耗兵源）
- 底部 **结束回合**：交给 AI 行动
- 右上 **+/−** 缩放；**重开** 重置；**载入** 导入 JSON 数据
- 手机上：单指拖动平移地图，轻点选中

### 规则要点

- **你是协约国**，AI 是德军。守住 16 回合、德军累计战果不到 30 即胜
- **兵力显示 0–100**，但实际按 4 个「段」离散结算（满编 / 减员 / 残破 / 濒危），不是血条
- **士气** 0–6，低士气不能进攻；本回合没开火就能恢复
- **炮兵** 射程 3、最小射程 2（贴脸打不了），远程射击降一列且不受反击
- **城镇** 既是战果来源也是兵源产地，要塞额外提供防御加成

## 编辑器

| 页签 | 能改什么 |
|---|---|
| **兵种** | 攻/防/移/射程/兵力/士气/费用，新增或删除兵种，实时看赔率 |
| **地图** | 涂地形、放城镇（可设要塞）、放部队、平移浏览；支持新建任意尺寸地图 |
| **势力** | 增删势力，配色、外形、阵营、兵源、集结区 |
| **战斗规则** | CRT 全表、赔率分界、段位、士气档、损失表、征兵参数 |
| **平衡预览** | 自动算出期望伤害矩阵与击杀次数，判断有没有超模兵种 |

### 存档

点 **保存并应用** → 写入浏览器 localStorage → 回游戏刷新即生效。
编辑器和游戏同站点，所以共享同一份存储。

**换设备 / 换浏览器**要用 JSON：
编辑器 **导出 JSON** → 游戏 **载入** 选择该文件。

> 不要用 `file://` 直接双击打开。那种模式下浏览器禁止读取相邻文件，编辑器和游戏不共享存储。GitHub Pages 是 http 服务，没有这个问题。

## 数据结构

游戏的全部可调参数都在这一个 JSON 块里（`index.html` 中 `<script type="application/json" id="GD">`）：

```
{
  "meta":     { "cols":64, "rows":64, "maxt":16, "gthr":30 },
  "units":    { "inf": { "n":"步兵师", "sym":"inf", "atk":4, "def":5, ... } },
  "terrain":  { "p": { "n":"平原", "f":"#e3d9bf", "def":1.0, "mv":1 } },
  "factions": [ { "id":"blue", "team":"ally", "player":true, "cap":40, ... } ],
  "crt":      [ ["A","A","A","EX","EX","D"], ... ],
  "rules":    { "segs":[...], "bands":[...], "lossPct":{...}, ... },
  "recruit":  { "perTurnCap":8, "moralePenalty":1, ... },
  "cities":   [ { "c":26, "r":22, "n":"布鲁塞尔", "w":4 } ],
  "map":      [ "ppfppp...", ... ],
  "oob":      { "blue":[{ "t":"inf","c":43,"r":12 }], "red":[...] }
}
```

想手改也行——改完在游戏里点「载入」导入即可。

## 已知限制

- AI 只会「打相邻/射程内弱者 → 向高价值城镇推进」，不会守桥、不会包抄
- 回合上限与战果阈值是全局的，多势力各自独立胜利条件尚未实现
- 只支持一个玩家势力，没有热座模式
- 炮兵缺少反炮兵机制，远程火力压制较强
